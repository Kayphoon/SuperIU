# SuperIU Capture

这是桌面包内的 Swift 子模块，包含 `SuperCapture`、`SuperClipboard` 和菜单栏进程 `SuperIUNative`。它独立于 Agent core 和远程服务器，最低系统为 macOS 14。Electron 通过子进程启动内置 helper，关闭 stdin 或发送 `quit\n` 时 helper 退出。

当前实现待 macOS 编译与实机验收。Linux 上的 Electron 生命周期测试不能证明 ScreenCaptureKit、AppKit、Vision 或性能指标通过。

## 构建

在 macOS 14+、安装 Xcode Command Line Tools 后，从仓库根目录运行：

```sh
swift test --package-path packages/desktop/native
swift build -c release --package-path packages/desktop/native
pnpm build
pnpm desktop
```

发布包的既有命令会编译并嵌入 `SuperIU Capture.app`，不依赖用户安装 Swift 运行环境：

```sh
pnpm --filter @agent/desktop run package:mac --no-install
open packages/desktop/dist/SuperIU.app
```

helper 的 bundle id 随正式版、开发版的宿主区分，后缀为 `.capture`。首次实际截图时请求屏幕录制权限。拒绝权限后保留原剪贴板，并提示在系统设置中授权；启动应用不会请求屏幕权限或辅助功能权限。

## 操作

| 操作 | 按键 |
| --- | --- |
| 呼出截图 | `Cmd+Shift+2` |
| 剪贴板历史 | `Cmd+Shift+V` |
| 框选、移动、八锚点缩放 | 鼠标拖动，`V` 返回选区工具 |
| 微移选区 | 方向键；`Shift` 加速至 10 pt |
| 矩形、马赛克 | `R`、`M`，随后在选区内拖动 |
| 红、黄、蓝 | `1`、`2`、`3` |
| 线宽 2 / 4 / 6 pt | `[`、`]` 或工具栏 |
| 撤销最后一处标注 | `Cmd+Z` |
| 复制图片 | `Enter` 或选区内双击 |
| 只识别并复制文字 | `Shift+Enter` 或 `Cmd+C` |
| 取消 | `Esc` |

复制图片后只对已经栅格化标注的最终图像运行 OCR，识别结果附在历史记录中，不会再次写入系统剪贴板。文字模式在识别期间发现剪贴板已变更时，不覆盖更新的内容。当前只允许一个 OCR 任务，识别期间不排队积累全尺寸图片。

截图浮层使用非激活 `NSPanel`，允许面板接收截图期间的按键，不激活 helper 应用。多个显示器采用各自的 AppKit 坐标和像素尺寸，跨屏结果按参与显示器的最高倍率合成。马赛克编辑预览显示为不透明遮挡，确认时输出像素化结果。

## 历史与隐私

默认历史全部在内存中：文本最多 200 条，图片最多 25 条，图片只保留最长边 128 px 的缩略图及 OCR 文本。默认不创建原图缓存目录，不把截图保存到桌面或文稿目录。退出后默认历史消失，未保存的图片历史不能复制出原图。

在菜单中显式打开“保存图片历史到缓存”后，**后续**图片才按内容 hash 保存为 PNG，文本与 OCR 元数据保存为有界 JSON。缓存位于 `~/Library/Caches/com.superiu.capture/`，目录权限 `0700`，文件 `0600`；图片不进入数据库 BLOB。关闭此开关会删除模块专属缓存，内存缩略图仍可查看。

图片 LRU 上限 25 张，最长保留 7 天，在读取和变更时清理。图片和元数据目录总预算为 50 MB（50,000,000 字节），写入图片前为元数据及原子写入预留空间，并逐出最旧的图片。系统可能主动清除 Caches，历史恢复会忽略已不存在的原图。

文本条目 UTF-8 上限 16 KiB，OCR 文本上限 32 KiB；图片边长上限 16384 px、像素总量上限 6400 万。超限条目不加入历史。监控器每 250 ms 只比较 `changeCount`，无变更时不读取内容或扫描磁盘。

任一 pasteboard item 包含 `org.nspasteboard.ConcealedType`、`org.nspasteboard.TransientType`、`org.nspasteboard.AutoGeneratedType` 或 `de.petermaurer.TransientPasteboardType` 时，整次复制不进入历史。启动时已有的剪贴板也不会被归档。

采用有界数组和子串检索，避免为最多 225 条记录引入 SQLite/FTS5 的额外状态与维护。检索包含文本及图片 OCR 元数据。接入遵循 SuperIU 既有“单核双壳”边界。按项目约定查阅了可用的 Alma 资料和安装包索引，但没有证实其相关原生截图机制，未将其作为已验证的参考实现。

## macOS 验收

以下场景需要真实 Mac 和已登录的图形会话。需要两台激活显示器覆盖多屏场景，至少一个 Retina 屏幕；不得用 Linux 单元测试或截图命令的输出代替实际浮层操作。

| 场景 | 精确调用与操作 | PASS 判据 | 证据 |
| --- | --- | --- | --- |
| 原生构建 | `swift test --package-path packages/desktop/native` | XCTest 全部通过；不得跳过 | 完整 stdout、stderr、退出码 |
| 内置打包 | `pnpm --filter @agent/desktop run package:mac --no-install`；`open packages/desktop/dist/SuperIU.app` | helper ready；菜单栏图标出现 | 构建日志、应用截图 |
| 复制与取消 | `computer.press("cmd+shift+2")`；`computer.drag([[100,100],[600,400]])`；`computer.press("enter")`；再次呼出后 `computer.press("esc")` | 首次有 PNG，浮层关闭；第二次 changeCount 不变 | 操作日志、截图、pasteboard 前后输出 |
| 矩形与打码 | 呼出并框选后 `computer.press("r")`；`computer.drag([[150,150],[250,250]])`；`computer.press("m")`；`computer.drag([[300,150],[400,250]])`；`computer.press("enter")` | 裁切图包含边框和不可还原的像素化区，OCR 输入为处理后图像 | 粘贴结果截图、动作日志 |
| OCR | 在 TextEdit 显示 `Hello 中文`；呼出框选该文字；`computer.press("shift+enter")`；`pbpaste` | 输出包含 `Hello` 和 `中文`，无 PNG；再用 Enter 复制后历史搜索能找到文字 | `pbpaste`、原生历史搜索截图 |
| 敏感项与容量 | 上述 XCTest 使用 `NSPasteboard.withUniqueName()` 写入四类标记、201 文本和 26 图片 | 敏感项 0；文本 200；图片 25；缩略图最长边 128；默认目录不存在 | XCTest 日志 |
| 缓存 | 菜单显式开启图片历史；复制图片；`du -sk ~/Library/Caches/com.superiu.capture`；关闭开关 | 开启后有 hash PNG；小于 48829 KiB；关闭后目录不存在 | 目录前后清单、菜单操作截图 |
| 宿主退出 | `pgrep -fl SuperIUNative`；退出 SuperIU；再执行 `pgrep -fl SuperIUNative` | helper 随宿主退出，无孤儿 | PID 和退出回读 |

八锚点、显示器负坐标、Retina 坐标翻转、跨屏不同倍率由几何 XCTest 覆盖；仍需在实际多屏浮层逐一拖动验证。桌面坐标取决于显示器布局，若上述坐标未落在测试屏幕内，应在动作日志中记录实际坐标和屏幕 frame。

性能验收应分别记录 helper 和整个 Electron 应用。35 MB 限制只针对新增原生 helper，不能宣称整个现有 Electron 宿主达到此值。使用 Activity Monitor 或 `ps -o pid,rss,%cpu -p <helper-pid>` 记录闲置、截图关闭后、OCR 结束后三种状态。通过输入时间和首个已显示面板帧记录唤起耗时，目标小于 80 ms。250 ms 轮询本身存在唤醒，`0.0%` 是采样显示目标，不是严格零 CPU 指令；当前没有这些性能指标的实测证据。
